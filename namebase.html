A functional guide for Handshake users

Namebase is a domain registry and registrar for the decentralized web. Among other things, you can acquire decentralized domains for up to 10 years and put them to use directly from its infrastructure.

How to host a website using a domain acquired on Namebase

Note: Namebase is a custodial service, and this guide covers its registrar service. Namebase also offers a non-custodial wallet, Namebase Wallet, which can do everything Bob Wallet does with a more modern and intuitive interface, though it is not open source. Both wallets are the best option for self-custody.

0. What you need

  • A Namebase account with a second-level domain (SLD).
  • For an HTTP site: a GitHub account and, optionally, a Vercel account for added privacy.
  • For an HTTPS site: the Castell app running on your Umbrel.

1. Get a domain on Namebase

To set up a website, you first need a domain. Namebase lets you register SLDs and rent them for up to 10 years. We won't cover the process in detail, but you will need some HNS or BTC, since those are the two payment options. A good-looking, cheap option is a .hns domain, such as yourname.hns.

🟡🔵 Namebase: Get a domain
1 Use the search bar to find and register a name that suits you.

Once you've made the payment, you have to wait for a few block confirmations to make sure the transaction is received. This can take up to 30 minutes. After that, your name should appear in your Domains menu. To manage it, go to Manage > DNS records.

🟡🔵 Namebase: Manage your domain
2 Your registered domains appear in the Domains menu. 3 Click Manage to open the DNS records section.

2. Set up an HTTP site on GitHub and Vercel

Setting up GitHub works the same way as in the Yeil DNS guide. Create a New repository, give it a name of your choice, and click Create repository.

In your new repository, click Add file → Create new file. Name the file index.html and add some HTML content in the editor, for example:

<h1>Hi, it's me!</h1>

Commit the changes.

Still on GitHub, open the Settings tab and scroll down to the Pages section. Set the source to the main branch and the / (root) folder, then click Save. After about 5 minutes, refresh the Pages section: a message at the top will show that your site is live at a URL similar to:

https://youraccount.github.io/yourrepository

Visit the site. At this point, your website is online.

In the Pages section, go to Custom domain and add your Namebase domain, such as:

yourdomain.hns

Because it is not an ICANN domain, GitHub will report that it doesn't work. Even though it will always show "DNS Check in Progress," your site will still be online. It takes around 30 minutes to go live.

🐈 GitHub: Pages settings
4 Your repository, with the CNAME file GitHub creates for your custom domain 5 Add your custom domain, “DNS Check in Progress” is expected

Finally, connect your Namebase domain to GitHub. In your Namebase DNS records, add an A record pointing to 185.199.111.153 (a GitHub Pages IP):

TypeHostValue
Ayourname.hns185.199.111.153
🟡🔵 Namebase DNS: New A record
6 Add an A record on Namebase pointing to a GitHub Pages IP. 7 Your site will be live at your domain

The new record can take up to about 6 hours to go live. After that, your site will be online at your domain:

http://yourname.hns/

Optional: Keep your repository private with Vercel

This last step is optional, and requires a free Vercel account. It's for when you want your site to stay online over HTTP while keeping its GitHub repository private. On GitHub's free plan, GitHub Pages only works with public repositories. If you make your repository private, your site goes offline. Vercel solves this: it reads your repository directly (even a private one) and serves the site itself, so the code can stay private while the site stays online.

How it works, in short: you connect GitHub to Vercel, import your website repository, add your domain in Vercel, and then add the DNS records Vercel gives you on Namebase. From then on, Vercel serves your site. Each time you push changes to GitHub, Vercel updates the site automatically.

▲ Deploying your site on Vercel
1 Create a new project in your Vercel account 2 Import your website repository from GitHub 3 Click "Import", once deployed then "Continue to Project" 4 Go to "Manage Domains" 5 Add your domain. As with GitHub Pages, it must be a second-level domain (SLD); a bare TLD won't work 6 Open the DNS records Vercel asks you to add 7 Add the A records on Namebase, the new IP will point to Vercel servers 8 Once the records propagate, your site will be online, and you can keep your GitHub repository private

Tip: if your site is plain HTML (no build tools), set Framework Preset to Other when importing. If you later see a 404: NOT_FOUND page, go to Settings → Build & Deployment, set the Output Directory to . (a single dot), and redeploy.

3. Set up an HTTPS site on Castell

Setting up Castell for your Namebase domains works the same way as described in the Castell guide. The only difference is that you use Namebase instead of Yeil, and the A record in Namebase must point to your VPS's IP address (or to your home network's IP if you follow path A). That said, we strongly recommend using a VPS (path B) if you want to keep your site online permanently.

🟡🔵 Namebase DNS: New A record
1 Copy the generated records on Castell and add them to Namebase. 2 The A record on Namebase must point to your VPS's IP.
